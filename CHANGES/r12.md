## Flags introduced
| flag | arm | off (r11 path) | on (r12 path) | requires |
|---|---|---|---|---|
| `flex_kernel` | 1a (kernel) | cuDNN SDPA `is_causal` on 64×1024 rows | FlexAttention (compiled `flex_attention`, `create_block_mask`); with `long_context` off it uses a per-row causal block mask, i.e. **the same attention pattern** | — |
| `long_context` | 1b (context) | 64 rows × 1024 tokens, attention stops at row boundaries, rotary positions 0..1023 per row | 1 row × 65,536 tokens, sliding window `q − kv < attn_window` (1024), rotary positions 0..65,535 | `flex_kernel` |
| `doc_masking` | 1b (unbundled sub-flag) | attention may cross the EOT token 50256 | `docs[q] == docs[kv]` (cumulative EOT count) | `flex_kernel` |
| `rotary_variant` | non-arm | `v11`: `inv_freq` on CPU in `__init__` | `v12`: `inv_freq` on device at first forward | — |

**Unbundled vs not.** The record bundles four things; all four are separate switches here. What the leaderboard
calls "64K context" is two mechanisms: the window stays **1024 tokens** but now slides across the former row
boundaries (`long_context`), and attention stops at document boundaries (`doc_masking`). `doc_masking` is also
defined on 1024-token rows, so it does not require `long_context`.

**Can the context sub-flag exist without the kernel?** Not in this trainer: `long_context` and `doc_masking`
require `flex_kernel` (start-up assert naming the flag). Semantically the 64K sliding-window mask is definable
with dense SDPA, but only with an attention implementation no record contains: either an explicit 65,536×65,536
boolean mask (4.29·10⁹ elements per micro-batch, and dense kernels then do 64× the windowed work) or a
hand-written banded/chunked SDPA. Neither is built (it would not be the record's code path). Consequence for
the matrix: `flex_kernel` is a prerequisite of every later attention mechanism, so "r18 minus the kernel" is
undefined — the same structure as the VE-ladder LOO problem (reported with it, not resolved).

**Arm 1a (kernel alone) is throughput-only by construction**: same pattern, same rows, same positions, same data;
only the kernel differs (equal up to rounding).

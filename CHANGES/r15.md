| `muon_ema_momentum` | 4b (bundled in "code optimizations"; separable) | `buf = m·buf + g; g = g + m·buf` | `buf.lerp_(g, 1 − m); g = g.lerp_(buf, m)` | — |
| `blockmask_manual` | 4b (bundled in "code optimizations"; separable) | `create_block_mask` from the token-level rule | block-level selection with window `ceil(w/128)` blocks + token-level `mask_mod` (`BlockMask.from_kv_blocks`) | `flex_kernel`, `long_context` |

**Unbundled vs not.** The README's two items become five switches. "U-net pattern value embeddings" =
`ve_unet` (+ `ve_lambdas2`, which came in the same PR but is mechanically independent). "Assorted code
optimizations" = `code_opts_15` (all changes with identical numerics, argued per hunk) plus two changes that are
**not** numerics-preserving and are therefore separate flags:

* `muon_ema_momentum`: proportional to the old form only while the momentum is constant; differs during the
  300-step momentum warmup.
* `blockmask_manual`: drops in-window (query, key) pairs whose key block is ⌈w/128⌉ blocks away
  (`tools/blockmask_check.py`, steady state, per query block):

  | window w (tokens) | 64 | 128 | 256 | 512 | 1024 | 1792 |
  |---|---|---|---|---|---|---|
  | in-window pairs dropped | 24.6% | 49.6% | 24.8% | 12.4% | 6.2% | 3.5% |

  (odd multiples of 64 lose 2,016 of the pairs, even multiples 8,128). The window grows 64 → 1792 over training,
  so the reduction is largest early. Arithmetic only; its effect on loss is not measured.

Per-hunk attribution between the two sub-arms is `provenance: inferred` (PR #43/#45 contents, gist, README).

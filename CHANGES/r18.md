## Bug fixed in this commit (affects rec-16 and rec-17 tags)
From rec-16 the optimizer setup took `transformer.vte` whenever `value_embeds` was on, but with `ve_split` the
tables live in `value_embeds`; presets r16/r17 would have raised at start-up. Fixed here (embedding Adam takes
`wte` + the `value_embeds` tables, as the records do), and the trainer now asserts at start-up that every
parameter is in exactly one optimizer. Static gates did not cover optimizer construction; the assertion is the
runtime guard. Tags rec-16/rec-17 are left unchanged (the history is the audit trail); use rec-18 or later.

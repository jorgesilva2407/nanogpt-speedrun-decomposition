## Flags introduced
| flag | arm | off (r15 path) | on (r16 path) | requires |
|---|---|---|---|---|
| `ve_split` | 5 (VE rung 3a) | one 50304×4608 table chunked into 6 | `value_embeds` module: 6 tables 50304×768, created after the blocks | `ve_unet` |
| `block_window` | 5 (rung 3b) | token window w with block selection ⌈w/128⌉ (r15) | window = n whole blocks, `mask_mod` = causal [& document] only; schedule in blocks `int(((1−f)·64 + f·1792 + 64)//128)` | `blockmask_manual` |

| `code_opts_16` | 5b (unannounced "MFU tweaks") | — | DDP `gradient_as_bucket_view=True`, `broadcast_buffers=False`; `set_stance(skip_guard_eval_unsafe=True)` from step 5; unbuffered shard reads; `enable_gqa=True`; no division when accum = 1 | — |

**What each change does (code reading).**
* `ve_split`: same parameter count and per-element init distribution; draws happen in a different order and
  after the blocks'. Any measured effect is an implementation effect (layout/kernels) or an init-realisation
  effect, not a change of model class.
* `block_window`: the same *number of selected blocks* as r15 at every step for N = 1480
  (`tools/window_schedule_check.py`), but the token-level cut inside the window's edge block is gone: a query
  sees between (n−1)·128+1 and n·128 keys. Relative to r15's manual mask this re-adds the pairs r15 dropped
  (24.6%–49.6% of in-window pairs at small windows, `tools/blockmask_check.py`) and adds keys beyond w.
* `blockmask_separate`: same attended set (full ⊆ nonzero and `mask_mod` is all-true on full blocks), different
  kernel loop structure → equal up to accumulation order.

**Unbundled vs not.** The relabelled README names three changes; all three are separate flags, plus
`code_opts_16` for the throughput tweaks the original title ("MFU tweaks") referred to. Module renames
(`embed`, `blocks`) are cosmetic (the flagged trainer keeps r11 names; the gate maps names).

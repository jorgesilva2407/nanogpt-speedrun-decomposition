## Flags introduced
| flag | arm | off (r12 path) | on (r13 path) | requires |
|---|---|---|---|---|
| `window_warmup` | 2 | fixed window `attn_window` (1024) | window = `q*((step/N * (end − start) + start)//q)` with start 64, end 1792, q 64 (int32 CUDA tensor, recomputed every step; validation uses the current step's window) | `flex_kernel` |

**Design decision (stated, not hidden).** `window_warmup` requires only `flex_kernel`, not `long_context`. On
1024-token rows (`long_context` off) the window is applied inside each row, so it restricts attention early in
training and becomes inert once it exceeds the row length (from ≈ step 0.55·N for start 64, end 1792). On 64K
rows it is the record's sliding window. Consequently "r11 + window_warmup" is defined (it also turns on
`flex_kernel`, which is throughput-only), but it measures a truncated version of the mechanism; requiring
`long_context` instead would make it a cumulative add-one-in. Listed as an open choice in the final report.

**Unbundled vs not.** The README row names one change. The snapshot diff also carries **unannounced retunes**:
Adam β₁ 0.9 → 0.8 (all three Adam optimizers), Muon lr 0.04 → 0.05, momentum warmup 500 → 300 steps,
`num_iterations` 1875 → 1750, cooldown 562 → 640. They are config fields, not flags: leave-one-out keeps r18's
values, add-one-in keeps r11's, so neither direction attributes them to window warmup.

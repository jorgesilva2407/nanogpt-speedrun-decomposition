## Flags introduced
| flag | arm | off (r13 path) | on (r14 path) | requires |
|---|---|---|---|---|
| `value_embeds` | 3 (VE rung 1) | value residual: every layer mixes the first layer's `v` (`v1`) | one `nn.Embedding(vocab, 12·768)` (`transformer.vte`, 463,601,664 parameters) chunked into 12 per-layer value embeddings; layer i mixes `vi[i]` with the same `(1 − lamb)·v + lamb·x` form; `vte` joins the embedding Adam (lr 0.6) | — |
| `rotary_variant` = `v14` | non-arm | `v12`: fp32 angles on device, tables cast to bf16 | `v14`: `inv_freq` is a registered buffer, so `model.bfloat16()` casts it; angles `outer(int64 t, bf16 inv_freq)` are bf16 and the tables stay bf16 | — |

**What "value embeddings" replaces.** At r14 the value-embedding table does not add to the value residual from
#9: it *replaces* it (the mixed-in tensor changes from `v1` to `vi`). Add-one-in (r11 + `value_embeds`)
therefore also removes the value residual; there is no historical configuration with both, and none is built.

**Rotary precision (non-arm, intervening).** Commit `30370b5` ("rotary refactor and leave cos/sin in fp32. fixes
#39") registers `inv_freq` as a buffer; the global `.bfloat16()` then converts it, so — reading the dtype rules,
not measured — angles for positions up to 65,535 are formed in bf16. Kept as its own switch because it is a
numerical change that no arm claims.

**Unbundled vs not.** Value embeddings: one flag (the record's only mechanism). Retune: `num_iterations` 1750 →
1530, cooldown 640 → 600 (config). Everything else in the diff is cosmetic/refactor (PR #31's accumulation
loop, `norm()`, `CastedLinear`, loader without `B`) or documentation.
